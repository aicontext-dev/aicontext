AIContext

Open format standard for AI coding assistant project context.
One source of truth. Every AI tool.

The specification is a draft (0.1.0-draft) and the tools are 0.x, so formats and behavior can still change. See the changelog.

The problem

Every AI coding assistant reads its own instruction file: AGENTS.md, CLAUDE.md, .github/copilot-instructions.md, .cursor/rules/, .windsurf/rules/, CONVENTIONS.md. A team that uses more than one tool writes the same project knowledge several times, and the copies drift apart.

The result

You write the knowledge once in .aicontext/ (plain markdown), and aicontext export generates each tool's file from it. The output is deterministic, so unchanged sources produce no diff, and CI can check that the generated files are up to date.

Before: the same text kept by hand 
AGENTS.md
CLAUDE.md
.github/copilot-instructions.md
.cursor/rules/project.mdc
After: one source, generated files 
.aicontext/        <- you edit this
  README.md
  constraints.md
  rules/ui.md

AGENTS.md          <- generated
CLAUDE.md          <- generated
...                <- generated

Try it

aicontext init --name my-project       # creates .aicontext/README.md and context.json
# edit .aicontext/README.md: what the project is, its stack, rules that must never be broken
aicontext validate                     # schema, recommended files, placeholders, possible secrets
aicontext export --target all          # writes AGENTS.md, CLAUDE.md, .github/copilot-instructions.md, ...
aicontext export --target all --check  # in CI: exit code 1 when the generated files are out of date
Created (agents): AGENTS.md

Is it for you?

A good fit
  • You or your team use two or more AI coding tools, or expect to.
  • You want project guidance reviewed in pull requests like code.
  • A large repository or monorepo, where scoped rules keep the always-on context small.
  • CI should catch drift, stray secrets and an unfinished context.
Probably not (yet)
  • You use a single tool and a short hand-written file already works: keep it.
  • You expect AIContext to write or judge the content: a passing validate only means the structure is right and no obvious placeholder or secret was found.
  • You need to enforce what an AI tool does: the context is guidance, not policy enforcement.

Your existing files

AIContext does not overwrite what you already have.

  • export replaces only files that carry the Auto-generated by aicontext export header. Any other existing file is a conflict: nothing is written until you pass --force.
  • aicontext init lists the hand-written instruction files it finds, and export --dry-run shows what would change. The user manual has a step-by-step migration recipe (chapter 11, B).
  • Export never writes or deletes outside the project, even through symlinks or junctions, and refuses a context.json that validate rejects.

Supported tools and their limits

ToolGenerated fileScoped rules (split layout)
GitHub Copilot.github/copilot-instructions.md.github/instructions/*.instructions.md
Claude CodeCLAUDE.md.claude/rules/*.md
Cursor.cursor/rules/*.mdc.mdc rules with globs or a description
Windsurf.windsurf/rules/*.mdrules with a glob or model-decision trigger
Devin (opt-in).devin/rules/*.mdsame format as Windsurf
AiderCONVENTIONS.mdnone (one file)
Tools that read AGENTS.mdAGENTS.mdnone; optional nested AGENTS.md per directory
  • The per-tool rule formats follow the vendors' documentation; they have not yet been verified against every tool in real projects.
  • Some tools read several of these files together (for example the Local agent of Copilot in VS Code reads AGENTS.md and CLAUDE.md too). aicontext status shows the context size per tool and these overlaps as an estimate.
  • A tool does not always read its file without help: Aider only reads CONVENTIONS.md when you start it with aider --read CONVENTIONS.md (or set read: CONVENTIONS.md in .aider.conf.yml), and some editors have settings for file-based instructions (for example in VS Code with Copilot). See “Does my tool read the generated file?” in the user manual.
  • The secret lint is a heuristic and does not replace a dedicated secret scanner.
